myHook

Take MESSAGE, STOP, HALT, ASSERT, run-time errors and GPFs away from the Clarion run-time library and decide for yourself what happens: ignore them, answer them for the user, hand them to your own code — and write every one of them to a log.

Quita a la librería de ejecución de Clarion sus propios diálogos —MESSAGE, STOP, HALT, ASSERT, errores de ejecución y GPF— y decide tú qué pasa: ignorarlos, responderlos por el usuario, pasarlos a tu código, y escribirlos todos en un registro.

OverviewResumen #

Add myHook - Global message/stop/halt interceptor once to the application and the run-time library's own dialogs stop being the run-time library's business. Every MESSAGE, STOP, HALT, failed ASSERT, run-time error and GPF passes through your object first.

Each of the six gets a default action. On top of that sits an ordered rule table that tests the message text, so one stray "Record Not Found" can be answered and logged while every other message still reaches the user untouched.

Where it fits Anywhere the built-in dialogs are a nuisance or a mystery — an unattended or overnight process that must never stop on a message box, a support case where you need to know what the user was told, a third-party or legacy module whose messages you cannot edit, or simply an audit trail of everything the program ever said.

Install & registerInstalar y registrar #

Three files ship together:

myHook.tpl
MsgHookClass.inc
MsgHookClass.clw
  1. Copy MsgHookClass.inc and MsgHookClass.clw to a folder on the Clarion redirection path — the application's own folder, or \clarion12\libsrc\win. Both must be ANSI with CRLF line endings (they are pure ASCII, so any editor will do).
  2. In the IDE: Setup ▸ Template Registry ▸ Register, and pick myHook.tpl.
  3. Open the application, Global Properties ▸ Extensions ▸ Insert, and choose myHook - Global message/stop/halt interceptor (add once).
  4. Fill in the tabs, then Generate.

MsgHookClass.clw carries a LINK attribute, so it pulls itself into the build — there is nothing to add to the project.

Nothing happens until Install() runs On the General tab, Start intercepting defaults to As soon as the program starts, which puts MsgHook.Install() in the program's setup code. Choose the other option if you want to configure things yourself first, then switch it on from an embed with the myHookHere code template.

The six eventsLos seis eventos #

Each has its own tab, its own tick box and its own default action. Nothing is intercepted unless you tick it — an event you leave alone behaves exactly as it always did.

TabCatchesRun-time property usedEquate
MESSAGEEvery MESSAGE()SYSTEM{PROP:MessageHook}Hook:Message
STOP and HALTEvery STOP()SYSTEM{PROP:StopHook}Hook:Stop
STOP and HALTEvery HALT()SYSTEM{PROP:HaltHook}Hook:Halt
ErrorsA failed ASSERT(){PROP:AssertHook} and {PROP:AssertHook2}Hook:Assert
ErrorsRun-time errorsSYSTEM{PROP:FatalErrorHook}Hook:Fatal
ErrorsGPFs / unhandled exceptionsSYSTEM{PROP:LastChanceHook}Hook:Exception
The GPF hook has only one seat PROP:LastChanceHook is a single slot for the whole process. If something else in the application already owns it — a GPF reporter, say — do not tick Intercept GPFs: the last one set wins and the other tool goes quiet.

An ASSERT also brings its source file and line with it; they arrive as MsgHook.Info.Module and MsgHook.Info.Line and go into the log. A GPF brings the exception code and the address it failed at, as Info.Code and Info.Address.

Cada uno tiene su pestaña, su casilla y su acción por defecto. No se intercepta nada que no marques: un evento que dejes en paz se comporta exactamente como siempre.

Un ASSERT trae además su fichero fuente y su línea; llegan como MsgHook.Info.Module y MsgHook.Info.Line y van al registro. Un GPF trae el código de excepción y la dirección donde falló, como Info.Code e Info.Address.

Not every action makes sense for every event, so each tab offers only the ones that do. The drop list on the MESSAGE tab, for instance, has no halt; the HALT tab has no ignore (see STOP and HALT).

Answering for the user

When the action is Answer — and also for Ignore and log and swallow — a second prompt appears asking which button to hand back: Ok, Yes, No, Abort, Retry, Ignore or Cancel. That value is what MESSAGE() returns to whoever called it, so it matters whenever the code behind the message tests the answer:

IF MESSAGE('Delete this record?','Delete',ICON:Question,BUTTON:Yes+BUTTON:No) = BUTTON:Yes
  DELETE(Orders)                        ! answering Yes here would delete silently
END
Think about what you are agreeing to Answering a question you have not read is how records get deleted. Prefer a rule matched on the exact wording over a blanket default of Answer Yes, and if the message is a question you do not recognise, answer No or Cancel rather than Ok.

If you leave the button unset, the class works one out: the message's own default button if it had one, otherwise the first of Ok, Yes, No, Retry, Ignore, Cancel, Abort that the message actually offered.

Ignore itHookDo:Ignore Se lo traga. Ninguna ventana. Para un MESSAGE, quien llamó recibe el botón que indicaste.
Answer it for the userHookDo:Answer Se lo traga y devuelve el botón que elegiste, como si el usuario lo hubiera pulsado.
Hand it to my procedureHookDo:Call Tu código se ejecuta y decide — ver Pasarlo a tu código.

Responder por el usuario

Cuando la acción es Answer —y también con Ignore y log and swallow— aparece un segundo prompt que pregunta qué botón devolver: Ok, Yes, No, Abort, Retry, Ignore o Cancel. Ese valor es lo que MESSAGE() devuelve a quien lo llamó, así que importa siempre que el código de detrás compruebe la respuesta:

IF MESSAGE('¿Borrar este registro?','Borrar',ICON:Question,BUTTON:Yes+BUTTON:No) = BUTTON:Yes
  DELETE(Orders)                        ! responder Yes aquí borraría en silencio
END
Piensa en lo que estás aceptando Responder a una pregunta que no has leído es como se borran registros. Es mejor una regla que case con el texto exacto que un valor por defecto general de Answer Yes; y si el mensaje es una pregunta que no reconoces, responde No o Cancel antes que Ok.

Si dejas el botón sin fijar, la clase deduce uno: el botón por defecto del propio mensaje si lo tenía, y si no el primero de Ok, Yes, No, Retry, Ignore, Cancel, Abort que el mensaje ofreciera de verdad.

RulesReglas #

The Rules tab is where myHook earns its keep. A rule tests the text of an event and, if it matches, gives that one its own treatment. Rules are checked in the order you entered them, the first match wins, and anything that matches nothing falls back to the default action for its kind of event.

PromptWhat it does
When it isAny of them, or just one kind: a MESSAGE, a STOP, a HALT, an ASSERT, a run-time error, a GPF.
Look atThe message text, the caption (title bar), or either of them.
TestAnything at all · Contains · Starts with · Is exactly · Matches, with * and ?
For this textWhat to look for. Not case sensitive.
Then do thisAny of the seven actions.
Answer withThe button, when the action is Answer.
Call this procedureThe procedure, when the action is hand it to my procedure.
Replace the text withNew wording, for show it as a plain message and show it as usual. Leave it empty to keep the original.

Worked examples

GoalWhenTestTextThen
Never show one particular nuisanceA MESSAGEContains Record Not FoundAnswer · Ok

Let one module's errors reach your codeA run-time errorStarts with InvalidHand it to my procedure

About the wildcard test * and ? match the whole string, the way a file mask does — so locked matches only a message that is exactly that word, while *locked* matches one that mentions it anywhere. ? is exactly one character.
No apostrophes in the rule text What you type goes into the generated source as a quoted Clarion string, so an apostrophe in For this text will break generation. Match on a stretch of the message that has none — a contains test rarely needs the whole sentence.
A rule only fires for an event you are intercepting The hook has to be in place before a rule can be consulted. A rule about STOPs does nothing until Intercept STOP is ticked on its tab.

La pestaña Rules es donde myHook se gana el sueldo. Una regla examina el texto de un evento y, si casa, le da a ese un trato propio. Las reglas se comprueban en el orden en que las escribiste, gana la primera que case, y lo que no case con ninguna recibe la acción por defecto de su tipo de evento.

What a line looks like

Readable text:

2026-07-27 09:13:45  [MESSAGE]  "Delete"  Delete this record?  -> answered No  {thread 1, Update an Order}
2026-07-27 09:13:45  [STOP]  "Stop"  a stop that should be ignored  -> ignored Ignore  {thread 1}
2026-07-27 09:13:45  [HALT]  "Halt"  shutting down  -> logged only  {thread 1}

CSV, with the heading row it writes into a new file:

"When","Event","What we did","Thread","Window","Caption","Text","Answer","Module","Line","Code"
"2026-07-27 09:16:29","MESSAGE","answered",1,"","Cap One","he said ""hi"", with  spaces","No","",0,0

Quotes inside a value are doubled the way a spreadsheet expects, and the message text is flattened to a single line — every line break or | becomes  | , so one event is always one row.

Why it is safe to share The file is opened for append and closed again on every line. Several threads can write to it, several copies of the program can write to it, and a line written immediately before a HALT is still on disk afterwards. It costs an open and a close per line, which is nothing next to a dialog the user has to read.

Your own lines

The myHookHere code template does this from an embed without you typing anything, and can also drop a one-line tally of everything seen so far.

Cómo es una línea

Texto legible:

2026-07-27 09:13:45  [MESSAGE]  "Delete"  ¿Borrar este registro?  -> answered No  {thread 1, Update an Order}
2026-07-27 09:13:45  [STOP]  "Stop"  a stop that should be ignored  -> ignored Ignore  {thread 1}
2026-07-27 09:13:45  [HALT]  "Halt"  cerrando  -> logged only  {thread 1}

CSV, con la fila de encabezados que escribe al crear el fichero:

"When","Event","What we did","Thread","Window","Caption","Text","Answer","Module","Line","Code"
"2026-07-27 09:16:29","MESSAGE","answered",1,"","Cap One","he said ""hi"", with  spaces","No","",0,0

Las comillas dentro de un valor se duplican como espera una hoja de cálculo, y el texto del mensaje se aplana a una sola línea: cada salto de línea o | se convierte en  | , así que un evento siempre es una fila.

Por qué se puede compartir sin riesgo El fichero se abre para añadir y se cierra otra vez en cada línea. Pueden escribir varios hilos, pueden escribir varias copias del programa, y una línea escrita justo antes de un HALT sigue estando en disco después. Cuesta una apertura y un cierre por línea, que no es nada al lado de un diálogo que el usuario tiene que leer.

Tus propias líneas

Write() añade una línea en crudo, así que tu código puede dejar notas en el mismo fichero:

La plantilla de código myHookHere hace esto desde un embed sin teclear nada, y también puede dejar un recuento de una línea con todo lo visto hasta el momento.

STOP and HALTSTOP y HALT #

A HALT cannot be called off The run-time library ends the program as soon as the halt hook returns, whichever action you pick. This was established by building a program against the class and running it — not assumed from the documentation.

So for a HALT, the choices change what is said on the way out and what lands in the log, not whether it happens:

On the tabWhat actually happens
Halt as usual, with its messageThe program ends and the message is shown, exactly as it would have been.
Halt, but say nothingThe program ends in silence — the message is swallowed.
Say something else, then haltYour wording is shown as an ordinary MESSAGE, then it ends.
Hand it to my procedure, then haltYour code runs first — a last chance to flush a file, close a connection or write a note — then it ends.
Write it to the log, then haltThe default. A line in the log, then it ends.

That is still worth having: an unexplained shutdown becomes a timestamped line naming the window that was on screen and the thread it happened on.

A STOP is different

STOP really can be ignored. Set it to Ignore it - carry on regardless and execution resumes on the line after the STOP, as though it had never been reached.

  STOP('this would normally offer Abort or Ignore')
  ! with Hook:Stop set to HookDo:Ignore, this next line runs
  post:Total += 1
Carrying on has consequences A STOP is usually there because something was wrong. Ignoring it means the code after it runs with whatever state caused the STOP in the first place. Use a rule so you only ignore the one you meant to, and log it.
Un HALT no se puede cancelar La librería de ejecución termina el programa en cuanto el hook de halt devuelve el control, elijas la acción que elijas. Esto se comprobó compilando un programa contra la clase y ejecutándolo, no se supuso a partir de la documentación.

Así que para un HALT las opciones cambian lo que se dice al salir y lo que queda en el registro, no si ocurre o no:

En la pestañaQué pasa de verdad
Halt as usual, with its messageEl programa termina y se muestra el mensaje, exactamente como habría sido.
Halt, but say nothingEl programa termina en silencio: el mensaje se lo traga.
Say something else, then haltSe muestra tu texto como un MESSAGE normal y luego termina.
Hand it to my procedure, then haltTu código se ejecuta primero —una última oportunidad de vaciar un fichero, cerrar una conexión o dejar una nota— y luego termina.
Write it to the log, then haltEl valor por defecto. Una línea en el registro y termina.

Aun así merece la pena: un cierre inexplicable se convierte en una línea con fecha y hora que nombra la ventana que había en pantalla y el hilo en el que ocurrió.

Un STOP es distinto

Un STOP sí se puede ignorar de verdad. Ponlo en Ignore it - carry on regardless y la ejecución sigue en la línea siguiente al STOP, como si nunca se hubiera alcanzado.

  STOP('esto normalmente ofrecería Abort o Ignore')
  ! con Hook:Stop en HookDo:Ignore, esta línea siguiente se ejecuta
  post:Total += 1
Seguir adelante tiene consecuencias Un STOP suele estar ahí porque algo iba mal. Ignorarlo significa que el código posterior se ejecuta con el mismo estado que provocó el STOP. Usa una regla para ignorar solo el que querías, y regístralo.

Three fields are yours to set on the way out:

SetTo
Info.ActionAny HookDo: value, to change your mind about what happens next
Info.AnswerThe BUTTON: value to hand back
Info.Handled1 to say it is dealt with — nothing more is shown

A named procedure

CheckTheMessage  PROCEDURE()
  CODE
  IF INSTRING('TIMEOUT',UPPER(MsgHook.Info.Text),1,1)
    MsgHook.Info.Action = HookDo:Answer         ! retry quietly, no window
    MsgHook.Info.Answer = BUTTON:Retry
  ELSE
    MsgHook.Info.Action = HookDo:Normal         ! let the user see anything else
  END

If the procedure is one of the application's own, AppGen has already prototyped it and there is nothing more to do. If it lives in hand-written source, tick Add a prototype for each procedure I named on the Advanced tab — each distinct name is added once, however many tabs and rules point at it.

Or derive TakeEvent yourself

The template generates a derived class whose TakeEvent() routes to the procedures you named. You can put code straight into it instead, through the embed myHook - your own code, every intercepted event:

%HookObject.TakeEvent PROCEDURE()
  CODE
  ! rule 2 asked for us
  IF SELF.Info.Tag = 2
    SELF.Info.Action  = HookDo:Answer
    SELF.Info.Answer  = BUTTON:Cancel
    SELF.Info.Handled = 1
  END

One quiet procedureUna procedure sin filtro #

Add the extension myHook - let this procedure be noisy (suspend interception) to a procedure and, while it is open, MESSAGE, STOP and the rest come out the normal way on that thread. The rules and the log sit that one out. Interception starts again when it closes.

Useful for a diagnostic window, a maintenance screen, or any procedure whose messages you genuinely want the user to see even though the rest of the application is muzzled.

It is generated into the ABC window manager's Init and Kill, so it suits window procedures. From anywhere else, call the pair yourself:

  MsgHook.Suspend()          ! this thread only
  ! ... whatever should be allowed to speak up
  MsgHook.Resume()
Per thread, on purpose Suspending is thread-local, so a background thread carries on being intercepted while the window in front of the user is free to talk. The hooks themselves are process-wide; it is the suspend flag that is per thread.

Añade la extensión myHook - let this procedure be noisy (suspend interception) a una procedure y, mientras esté abierta, MESSAGE, STOP y los demás salen de la forma habitual en ese hilo. Las reglas y el registro se quedan al margen. La interceptación vuelve al cerrarse.

Útil para una ventana de diagnóstico, una pantalla de mantenimiento, o cualquier procedure cuyos mensajes sí quieras que el usuario vea aunque el resto de la aplicación esté amordazada.

Se genera en el Init y el Kill del gestor de ventanas de ABC, así que encaja con procedures de ventana. Desde cualquier otro sitio, llama tú al par:

  MsgHook.Suspend()          ! solo este hilo
  ! ... lo que deba poder hablar
  MsgHook.Resume()
Por hilo, a propósito La suspensión es local al hilo, así que un hilo en segundo plano sigue interceptado mientras la ventana que tiene delante el usuario puede hablar. Los hooks en sí son de todo el proceso; lo que es por hilo es la bandera de suspensión.

Class referenceReferencia de la clase #

The object the template declares is global, so every one of these can be called from any embed. The default name is MsgHook.

Setting it up

MethodWhat it does
Init()Back to defaults: nothing watched, no rules, no log.
SetEvent(event, action, answer)Watch one event and give it its default action. answer is optional.

How it worksCómo funciona #

The Clarion run-time library will hand its own dialogs over to your code if you give it the address of a replacement procedure. There is one property per dialog, all on SYSTEM, and all listed in \clarion12\libsrc\win\property.clw as part of the PROP:LibHook family.

The exact prototypes those replacements must have are not guessed here: they are copied from \clarion12\libsrc\win\WBHOOK.CLW, the shipped WebBuilder layer, which uses the same seven hooks to move a desktop MESSAGE onto a web page. That is also where the odder details come from — the buttons bitmap, for example, arrives at the message hook as a string.

Install() sets the properties to ADDRESS() of module-level procedures in MsgHookClass.clw; those hand straight over to the object. Remove() sets them back to 0.

Letting one through

To show a message the normal way, the class has to lift its own hook first — otherwise the run-time library would call straight back into it and go round for ever:

saved = SYSTEM{PROP:MessageHook}
SYSTEM{PROP:MessageHook} = 0
answer = MESSAGE(...)                  ! the real one
SYSTEM{PROP:MessageHook} = saved
The gap that opens That gap is a few milliseconds wide and it is process-wide, so a MESSAGE raised on another thread during it goes out un-intercepted. The run-time library's own hook code does exactly the same thing. If that matters for your case, answer rather than pass through — an answered message never calls the real MESSAGE() at all.

One per program

The hooks are process-wide, so the last object to call Install() is the one the run-time library talks to. One object, added once, is the intended arrangement.

La librería de ejecución de Clarion entrega sus propios diálogos a tu código si le das la dirección de una procedure sustituta. Hay una propiedad por diálogo, todas sobre SYSTEM, y todas listadas en \clarion12\libsrc\win\property.clw como parte de la familia PROP:LibHook.

Los prototipos exactos que deben tener esas sustitutas no se han adivinado aquí: están copiados de \clarion12\libsrc\win\WBHOOK.CLW, la capa WebBuilder que se distribuye con Clarion y que usa los mismos siete hooks para llevar un MESSAGE de escritorio a una página web. De ahí salen también los detalles más raros: el mapa de bits de los botones, por ejemplo, le llega al hook de mensaje como una cadena.

Install() pone en las propiedades el ADDRESS() de unas procedures de módulo de MsgHookClass.clw, que se lo pasan directamente al objeto. Remove() las deja otra vez a 0.

Dejar pasar uno

Para mostrar un mensaje de la forma normal, la clase tiene que quitar antes su propio hook; si no, la librería la volvería a llamar y daría vueltas para siempre:

saved = SYSTEM{PROP:MessageHook}
SYSTEM{PROP:MessageHook} = 0
answer = MESSAGE(...)                  ! el de verdad
SYSTEM{PROP:MessageHook} = saved
El hueco que se abre Ese hueco dura unos milisegundos y afecta a todo el proceso, así que un MESSAGE lanzado en otro hilo durante ese instante sale sin interceptar. El propio código de hooks de la librería hace exactamente lo mismo. Si eso importa en tu caso, responde en vez de dejar pasar: un mensaje respondido no llega a llamar al MESSAGE() real.

Uno por programa

Los hooks son de todo el proceso, así que el último objeto que llame a Install() es aquel con el que habla la librería. Un objeto, añadido una vez, es la disposición prevista.
