graficaBarra

Simple bar graphs for Clarion windows and reports, drawn entirely with native BOX / LINE / SHOW primitives. On a report the graph goes into the band as vector primitives — never a bitmap — so PDF exports stay as small as possible.

Gráficos de barras sencillos para ventanas e informes de Clarion, dibujados por completo con las primitivas nativas BOX / LINE / SHOW. En un informe el gráfico entra en la banda como primitivas vectoriales — nunca un mapa de bits — así que los PDF salen lo más pequeños posible.

Pure Clarion · no DLLs · window + report · ABC chainClarion puro · sin DLLs · ventana + informe · cadena ABC

OverviewResumen

One self-contained ANSI class, GraficaBarraClass, holds up to 48 bars (label, value, color) plus the look — title, value/scale labels, gridlines, gaps, colors, automatic or fixed scale — and renders itself wherever the current graphics target is. Three template registrations drive it:

RegistrationScopeWhat it does
graficaBarraGlobalApplication (Global → Extensions) Adds INCLUDE('GraficaBarraClass.INC'),ONCE. Add it once; the other two require it.
graficaBarraProcedure with a WINDOW Draws the graph into an IMAGE control. Redraws on open and resize, and generates a Refresh:<Object> routine that re-reads variable bar values. Add once per graph — several graphs per window are fine.
graficaBarraReportProcedure with a REPORT Draws the graph into the detail band at %BeforePrint under SETTARGET(Report) using vector BOX/LINE/SHOW. A placeholder control supplies only the position and size, and is hidden at print time.
Driving it from code? For how the class works internally and worked example code (in English and Spanish), see the developer's reference.
templates/graficaBarra/
├─ graficaBarra.tpl          — the template set (register this)
├─ GraficaBarraClass.inc   — the class (config + prototypes)
└─ GraficaBarraClass.clw   — the implementation (scale + drawing)

Features: automatic "nice" scale (the maximum rounds up to 1, 2 or 5 × 10k) or a fixed SetRange(min,max); negative values hang below the zero baseline; numeric value over each bar; bar labels under the baseline; left-axis scale numbers; horizontal gridlines; per-bar colors or an automatic professional palette; configurable gap; an optional painted background. If the bar list is left empty the graph draws six sample bars — a built-in self-test.

Una sola clase ANSI autosuficiente, GraficaBarraClass, guarda hasta 48 barras (etiqueta, valor, color) y además el aspecto — título, etiquetas de valor y escala, líneas de rejilla, separación, colores, escala automática o fija — y se dibuja donde esté apuntando el destino gráfico actual. Características: escala "bonita" automática (el máximo redondea hacia arriba a 1, 2 o 5 × 10k) o un SetRange(min,max) fijo; los valores negativos cuelgan por debajo de la línea de cero; valor numérico sobre cada barra; etiquetas de barra bajo la línea base; números de escala en el eje izquierdo; líneas de rejilla horizontales; colores por barra o una paleta profesional automática; separación configurable; y un fondo pintado opcional. Si dejas la lista de barras vacía, el gráfico dibuja seis barras de ejemplo — una autoprueba incorporada.

Install & registerInstalar y registrar

  1. Copy GraficaBarraClass.inc and GraficaBarraClass.clw to a folder on the Clarion redirection path — your app folder or \clarion12\libsrc\win. Keep them ANSI (not UTF-8), CRLF line ends.
  2. Copy graficaBarra.tpl anywhere convenient (e.g. \clarion12\accessory\template\win) and register it: IDE → Setup → Template Registry → Register → pick the .tpl.
  3. In your app: Global → Extensions → Insert → graficaBarraGlobal (it is also added automatically the first time you add one of the other two).
  1. Copia GraficaBarraClass.inc y GraficaBarraClass.clw a una carpeta del camino de redirección de Clarion — la carpeta de tu app o \clarion12\libsrc\win. Mantenlos en ANSI (no UTF-8), con finales de línea CRLF.
  2. Copia graficaBarra.tpl donde te resulte cómodo (por ejemplo \clarion12\accessory\template\win) y regístralo: IDE → Setup → Template Registry → Register → elige el .tpl.
  3. En tu app: Global → Extensions → Insert → graficaBarraGlobal (también se agrega sola la primera vez que insertas una de las otras dos).

On a windowEn una ventana

  1. Put an IMAGE control on the window where the graph should live (no picture needed — it is just the canvas).
  2. Procedure → Extensions → Insert → graficaBarra - Draw a bar graph on this window.
  3. Pick the IMAGE control, set a title, and define the bars on the Bars tab.

Each bar's value is either a literal number or a variable / field / expression. After data changes, call the generated routine:

! the bars re-read their variables/expressions, then the graph redraws
DO Refresh:Graph1

The graph redraws itself on window open and resize (the draw is POSTed as a private event so it runs after the ABC resizer settles). Multiple graphs per window each target their own IMAGE, so they never erase each other.

  1. Pon un control IMAGE en la ventana donde deba ir el gráfico (no necesita imagen — es solo el lienzo).
  2. Procedimiento → Extensions → Insert → graficaBarra - Draw a bar graph on this window.
  3. Elige el control IMAGE, pon un título y define las barras en la pestaña Bars.

El valor de cada barra es o un número literal o una variable / campo / expresión. Después de que cambien los datos, llama a la rutina generada:

! las barras releen sus variables/expresiones y el gráfico se redibuja
DO Refresh:Graph1

El gráfico se redibuja solo al abrir la ventana y al redimensionar (el dibujo se envía con POST como evento privado para que ocurra después de que el redimensionador de ABC se asiente). Varios gráficos en una ventana apuntan cada uno a su propio IMAGE, así que nunca se borran entre sí.

On a report — small-PDF vector outputEn un informe — salida vectorial, PDF pequeño

This is the reason graficaBarra exists: report graphs that export to the smallest possible PDF. Instead of rasterizing into an image, the template draws the graph straight into the band being printed with native vector primitives:

SETTARGET(MyReport)                ! the band being printed becomes the target
RptGraph1.Paint(?GraphPlace)       ! BOX / LINE / SHOW vector primitives at the placeholder's rect
?GraphPlace{PROP:Hide} = 1         ! the placeholder itself never prints
SETTARGET()

Every bar is a filled BOX, the axis and gridlines are LINEs and all text is SHOW — these travel through the report engine (and the PDF output generator) as vector records, not pixels, so file size stays tiny and the graph prints razor-sharp at any resolution.

Setup

  1. In the report designer, put a placeholder control in the DETAIL band sized where the graph should print — an empty IMAGE works best (a BOX also works). Its AT() rectangle is the graph rectangle.
  2. Procedure → Extensions → Insert → graficaBarraReport - Draw a bar graph on this REPORT.
  3. Pick the placeholder, define the bars (values are usually fields/expressions — they are evaluated for every record printed), done. The placeholder is hidden at print time by default so it never shows itself.
Where it draws The code runs in the Before Printing Detail Section embed, so the placeholder must be in the detail band that is being printed. One graph is drawn per detail printed — for a single summary graph, print one summary detail line (or use the runtime API from any embed that prints a band).

Esta es la razón de ser de graficaBarra: gráficos en informes que exportan al PDF más pequeño posible. En lugar de rasterizar a una imagen, la plantilla dibuja el gráfico directamente en la banda que se está imprimiendo con primitivas vectoriales nativas:

SETTARGET(MyReport)                ! la banda que se imprime pasa a ser el destino
RptGraph1.Paint(?GraphPlace)       ! BOX / LINE / SHOW vectoriales en el rectángulo del marcador
?GraphPlace{PROP:Hide} = 1         ! el marcador en sí nunca se imprime
SETTARGET()

Cada barra es un BOX relleno, el eje y la rejilla son LINEs y todo el texto es SHOW — todo eso viaja por el motor de informes (y por el generador de PDF) como registros vectoriales, no como píxeles, así que el archivo se queda diminuto y el gráfico se imprime nítido a cualquier resolución.

Puesta en marcha

  1. En el diseñador de informes, pon un control marcador en la banda DETAIL del tamaño que deba tener el gráfico — un IMAGE vacío va perfecto (un BOX también sirve). Su rectángulo AT() es el rectángulo del gráfico.
  2. Procedimiento → Extensions → Insert → graficaBarraReport - Draw a bar graph on this REPORT.
  3. Elige el marcador, define las barras (los valores suelen ser campos/expresiones — se evalúan en cada registro que se imprime) y listo. El marcador se oculta al imprimir por defecto, así que nunca se ve.
Dónde dibuja El código va en el embed Before Printing Detail Section, así que el marcador tiene que estar en la banda de detalle que se imprime. Se dibuja un gráfico por cada detalle impreso — para un único gráfico de resumen, imprime una sola línea de detalle de resumen (o usa la API en ejecución desde cualquier embed que imprima una banda).

Changing it at run timeCambiarlo en ejecución

The object is plain procedure data — drive it from any embed:

Graph1.ClearBars()                       ! start over
Graph1.AddBar('Ene', Ene:Total)          ! auto palette color
Graph1.AddBar('Feb', Feb:Total, 04657C0h)! explicit BGR color
Graph1.Title = 'Ventas 2026'
Graph1.SetRange(0, 200)                  ! fixed scale (AutoScale off)
Graph1.Draw(MyWindow, ?Graph)            ! window redraw now
! or, if the bars came from the template prompts:
DO Refresh:Graph1                        ! reload prompt bars + redraw
Reports Call the same API in a report embed before the band prints, then SETTARGET(Report) ; RptGraph1.Paint(?Placeholder) ; SETTARGET() — or just let the template's generated %BeforePrint code do it.

El objeto es sencillamente un dato del procedimiento — manéjalo desde cualquier embed:

Graph1.ClearBars()                       ! empezar de cero
Graph1.AddBar('Ene', Ene:Total)          ! color de la paleta automática
Graph1.AddBar('Feb', Feb:Total, 04657C0h)! color BGR explícito
Graph1.Title = 'Ventas 2026'
Graph1.SetRange(0, 200)                  ! escala fija (AutoScale apagado)
Graph1.Draw(MyWindow, ?Graph)            ! redibujar la ventana ahora
! o, si las barras vinieron de los prompts de la plantilla:
DO Refresh:Graph1                        ! recargar las barras del prompt y redibujar
Informes Llama a la misma API en un embed del informe antes de que se imprima la banda, y luego SETTARGET(Report) ; RptGraph1.Paint(?Marcador) ; SETTARGET() — o simplemente deja que lo haga el código %BeforePrint que genera la plantilla.

TroubleshootingSolución de problemas

SymptomCause / fix
"File not found: GraficaBarraClass.INC" at compileThe .inc/.clw are not on the redirection path — copy both beside the app or into \clarion12\libsrc\win.
Template will not registerThe .tpl was re-saved as UTF-8 with BOM or with LF line ends — keep ANSI/CRLF.
Six sample bars appear instead of my dataThe Bars list is empty for that instance (that's the self-test). Add bars, or feed the object with AddBar() from an embed.
Window graph doesn't update after data changesCall DO Refresh:<Object> — bars with variable values are only re-read there (and at window open).
Report graph missingThe placeholder must be in the detail band being printed; the code runs at Before Printing Detail Section.
Report text looks too big / smallText metrics assume roughly a 10pt band font. Set RptGraph1.TextW / TextH (thousandths of an inch) in an embed before printing.
Bars in a strange colorClarion colors are BGR longs, not RGB — 0B6752Eh is steel blue.
