What emailTo is

emailTo sends e-mail from a Clarion application. It is three classes, one bundled C file and five templates, and it deploys as part of your .EXE — there is no DLL to ship, no .NET, no OpenSSL and nothing to register on the machine it runs on.

It can put a message on the wire four ways, and they all send the same message: SMTP over plain, STARTTLS or implicit TLS; the Gmail API; Microsoft Graph; or a provider API key for SendGrid, Mailgun, Resend, Brevo, Postmark and Mailjet.

You haveUseWhat you need
A Gmail accountSMTP + app passwordTwo-factor on, then an app password
Outlook.com or HotmailSMTP + OAuth2A desktop client ID from Azure
Microsoft 365 at workGraph, or SMTP + OAuth2A desktop client ID, and your tenant

Install

Copy these seven files to a folder on the Clarion redirection path — the application folder, or \clarion12\accessory\libsrc\win:

FileWhat it is
EmailNetClass.inc / .clwSockets, TLS, HTTPS, DPAPI. Compiles the C in.
EmailMsgClass.inc / .clwThe message and its MIME. Pure Clarion.
EmailToClass.inc / .clwAccounts, the four transports, OAuth2, the windows.
emailc.cWinsock, SCHANNEL, WinHTTP, DPAPI, SHA-256.

Put emailTo.tpl in \clarion12\accessory\template\win and register it — in the IDE, or from a command line:

ClarionCL.exe -tr "C:\clarion12\accessory\template\win\emailTo.tpl"

The sources must be ANSI, with CRLF line endings

Clarion mis-parses an LF-only include: you get Illegal data type: EMAILTOCLASS reported at the declaration, with nothing flagged inside the include itself. If you have moved these files through a tool that rewrites line endings, convert them back before hunting for a phantom syntax error.

The smallest thing that sends

No template, no window, no dictionary. This is a complete program:

  PROGRAM

  INCLUDE('EmailToClass.INC'),ONCE

  MAP
  END

Mailer  EmailToClass

  CODE
  Mailer.Init(PATH() & '\mail.ini')          ! where the account is remembered

  Mailer.SetProvider(ETPrv:Gmail)             ! host, port, security, sign-in
  Mailer.Acc.UserName = 'you@gmail.com'
  Mailer.Acc.Password = 'abcd efgh ijkl mnop' ! a Google APP PASSWORD, not your own
  Mailer.Acc.FromAddr = 'you@gmail.com'
  Mailer.Acc.FromName = 'Acme Dispatch'

  IF Mailer.SendSimple('bob@example.com', 'It works', 'Sent from Clarion.')
    MESSAGE('Sent.')
  ELSE
    MESSAGE(CLIP(Mailer.LastErrorText))
  END

Two things are worth noticing. SetProvider fills in the host, the port, the security and the sign-in method for you, so the only lines left are the ones that are actually about your account. And nothing here checks a return code except the send itself — every failure ends up in LastErrorText as a sentence you can show a user.

Where the app password comes from

Google, Yahoo and iCloud will not accept your normal password from a program. Turn on two-factor authentication, then generate an app password — a sixteen-character string issued for one application. Paste that into Acc.Password. Outlook.com no longer offers this route at all: it is OAuth2 or nothing, which the Programmer's Guide covers.

Building it by hand

The class files pull themselves into the build through their LINK attribute, and EmailNetClass.clw pulls in the C through its PRAGMA, so a hand-coded project needs no file list. It does need the two link-mode defines that the template would otherwise write for you:

<Project DefaultTargets="Build" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <PropertyGroup>
    <DefineConstants>_ABCDllMode_=&gt;0%3b_ABCLinkMode_=&gt;1%3b_emailToDllMode_=&gt;0%3b_emailToLinkMode_=&gt;1</DefineConstants>
  </PropertyGroup>
</Project>

Leaving the defines out does not fail to link

Without _emailToLinkMode_ the classes link as imports from a DLL that is not there, and the program takes an access violation inside a constructor before main() runs. The call stack shows nothing of yours on it, so it looks like anything except a project setting.

The same thing from AppGen

Two steps, and no code:

  1. Global Properties → Extensions → Insert → emailTo - Global. Fill in the Account tab: provider, from address, user name. That declares the object, sets the defaults and loads the stored account at start-up.
  2. Drag emailTo - E-mail button onto a window. Choose what it does — open the compose window, send a fixed message, or open the account setup window — and you are finished.

From any embed anywhere else in the application, the object is simply there:

Mailer.SendSimple(Cus:Email, 'Your statement', 'Attached.', Loc:PdfName)

A message with more in it

SendSimple covers a note with one attachment. Anything richer is built on Mailer.Msg and handed to Send:

  Mailer.Msg.ClearAll()
  Mailer.Msg.AddTo('bob@example.com', 'Bob Smith')
  Mailer.Msg.AddCc('accounts@acme.com')
  Mailer.Msg.SetSubject('Invoice ' & CLIP(Inv:Number))
  Mailer.Msg.SetText('The invoice is attached.')
  Mailer.Msg.SetHtml('<p>The invoice is <b>attached</b>.</p>')
  Mailer.Msg.Attach('C:\invoices\INV-1042.pdf')

  IF NOT Mailer.Send(Mailer.Msg)
    Mailer.ShowError()
  END

You do not tell it what kind of MIME document to build. Text alone is text/plain; text and HTML together become multipart/alternative; an inline image makes it multipart/related; a file attachment wraps the lot in multipart/mixed. A plain note does not arrive as a four-part tree.

The demo

examples/emailTo/emailToDemo.clw is the hand-coded equivalent of what the templates generate: a window with Account setup, Write a message and Send a test, and the conversation log underneath. Build it and press the buttons before wiring anything into your own application.

MSBuild emailToDemo.cwproj -t:Build -p:Configuration=Debug -p:Platform=Win32
emailToDemo.exe            ! the demo window
emailToDemo.exe /setup     ! straight to the account window

Test account is the button to press first. It connects, negotiates TLS and authenticates, then hangs up — it sends nothing to anybody, so you can prove the credentials without mailing a real person.

When the first send does not work

Turn the log on (Mailer.Trace = 1) and read the Log tab of the setup window. Every line the server said is there, with passwords masked. These are the answers that come up first:

What you seeWhat it means
The password was refused on GmailA normal password, not an app password. Or two-factor is off, so Google will not issue one.
The password was refused on Outlook.comMicrosoft turned basic authentication off for personal accounts. Use OAuth2.
The TLS handshake failed, Windows code 590624That is SEC_I_INCOMPLETE_CREDENTIALS. emailTo already handles it; if you see it, you are running an older copy of emailc.c.
Could not connect to the mail serverA firewall, or the wrong port. 587 is STARTTLS, 465 is implicit TLS, 25 is plain.
The sender was refusedThe From address is not one the account is allowed to send as.
Illegal data type: EMAILTOCLASS at compile timeThe includes arrived with LF line endings. Convert them to CRLF.
