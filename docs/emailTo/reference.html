How to read this

Every signature on this page was read out of the shipped .inc files when the page was built, so it is the signature in your build. Every member carries a line of real code — the build fails if one does not.

Mailer throughout is the global EmailToClass object the template declares. PROC on a signature means the return value may be ignored; VIRTUAL means it is meant to be overridden.

ClassLives inWhat it is
EmailNetClassEmailNetClass.incThe transport primitives, and the only class that touches C. A socket, optionally wrapped in TLS; an HTTPS request; the OAuth2 loopback redirect; DPAPI, SHA-256 and secure random.
EmailBufClassEmailMsgClass.incA growing byte buffer. Building MIME means appending thousands of small pieces to something that ends up megabytes long, and Clarion has no string builder - this doubles its capacity instead, so building stays linear.
EmailMsgClassEmailMsgClass.incThe message, and the MIME document it turns into. Pure Clarion: nothing here touches a socket, which is why all four transports can share it.
EmailOAuthClassEmailToClass.incThe OAuth2 authorisation-code flow with PKCE. It borrows the network and encoder objects from EmailToClass and owns neither.
EmailToClassEmailToClass.incThe sender. It owns an account and knows four ways to put a message on the wire, plus the setup and compose windows.

Every one of these DLLs ships with Windows

ws2_32, secur32, winhttp, crypt32, advapi32 and shell32 are bound at run time with LoadLibrary, so there is no import library, nothing to redistribute, and a machine missing one gives a clean error code rather than failing to start.
